Architecture Guide & Takeaway

RoboMission Fleet — App Map

A complete architectural tour of the browser-based warehouse autonomous mobile robot (AMR) simulator.

📦 System Overview

RoboMission Fleet simulates an autonomous warehouse robot navigating a 16×12 grid. It accepts plain-English natural language commands, extracts structured task intent via a dual-mode parser (Gemini LLM with instant offline regex fallback), calculates optimal shortest paths using 4-way Manhattan A*, navigates step-by-step with real-time explainability telemetry, and dynamically detours around live user-dropped obstacles.

🗺️ The Architectural Tour (Key Stops)

Trace a complete mission from user input to dynamic canvas execution across three foundational source modules:

src/parser/missionParser.ts parseMission(prompt)

Stop 1: Intent Extraction & Zero-Latency Fallback. Accepts the natural language string from the input field or preset buttons. If a Gemini API key is configured, it requests a structured JSON schema. If the API key is absent, times out (> 2.5s), or encounters a network error, it instantly delegates to fallbackParser.ts, extracting cargo and destination without breaking offline demo reliability.

src/planner/astar.ts findPath(start, goal, world)

Stop 2: Deterministic A* Shortest Pathfinding. Evaluates 4-directional cardinal neighbors using Manhattan distance heuristics. Treats static industrial shelves, grid borders, and placed obstacles as impassable cells. Computes the optimal route in sub-millisecond time (< 0.2ms) and returns an array of coordinates or null when trapped.

src/sim/simulationManager.ts onObstacleToggled(coord, added)

Stop 3: Live Collision Detection & Dynamic Replanning (The Climax). Triggers when the user clicks the grid. If an obstacle drops directly onto the robot's upcoming path vector, transit immediately halts, state transitions to REPLANNING, and an A* detour query runs from the robot's current cell. The remaining path line dynamically updates and transit resumes with live telemetry narration.

🔧 "To Change This, Start Here"

Quick reference anchors for modifying simulator behavior:

Warehouse Grid & Shelves

Edit src/world/warehouseWorld.ts in initDefaultLayout() to rearrange static racks or add new item stations.

Robot Movement Speed

Adjust baseStepIntervalMs in src/sim/simulationManager.ts (currently 300ms at 1x, 150ms at 2x).

Visual Theme & Glow

Modify colors, badges, and canvas glow effects in src/style.css and src/render/canvasRenderer.ts.

Keyword Synonyms & Presets

Add new natural language phrases in src/parser/fallbackParser.ts or update buttons in src/ui/controls.ts.

💡 A Practice to Reuse: Plan-First Verification

The Project Moment: During development, we tested deliberate failure cases: enclosing a delivery zone with hazard barriers to verify that the simulator transitions gracefully to BLOCKED rather than freezing or crashing.

Why It Matters: When building interactive systems with autonomous loops, specifying observable error states and mechanical unit tests upfront (such as Trapped Goal routing in astar.test.ts and simulationManager.test.ts) eliminates edge-case uncertainty early. When a bug occurred (e.g. reset() accidentally wiping obstacles in Preset 4), having crisp acceptance criteria made diagnosing the root cause instant.

Reuse on Your Next Project: Before writing any complex asynchronous or agentic workflow, define the exact failure mode first: what the system should log, what state badge should display, and how the user recovers.
